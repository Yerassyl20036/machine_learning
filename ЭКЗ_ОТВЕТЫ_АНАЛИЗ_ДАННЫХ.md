## БИЛЕТ №1
**1. Понятие данных и информационных моделей**

**Данные** — сырые факты, символы или наблюдения без контекста (числа, строки, сигналы). **Информация** — данные + контекст + интерпретация. **Знание** — информация + понимание закономерностей.

**Информационная модель** — абстрактное описание структуры и семантики данных:
- **Реляционная модель** — данные в таблицах (кортежи + атрибуты), связи через внешние ключи
- **Иерархическая** — древовидная структура (XML, JSON)
- **Сетевая** — граф связей
- **Объектно-реляционная** — объекты + таблицы (PostgreSQL)
- **Документная** — самоописывающиеся документы (MongoDB)

**2. Классификация типов данных в аналитике**

По структуре: **структурированные** (таблицы), **полуструктурированные** (JSON, XML), **неструктурированные** (текст, изображения).

По статистическому типу:
- **Количественные**: непрерывные (рост, вес), дискретные (количество)
- **Качественные/Категориальные**: номинальные (пол, страна — нет порядка), порядковые (оценки A/B/C — есть порядок)

По временному характеру: **кросс-секционные** (срез в один момент), **временные ряды** (изменение во времени), **панельные** (несколько субъектов, несколько периодов).

**3. Этапы жизненного цикла данных**

1. **Generation** — создание данных (транзакции, датчики, пользовательские действия)
2. **Collection** — сбор из источников (ETL, API, web scraping)
3. **Processing** — очистка, трансформация, обогащение
4. **Storage** — хранение (БД, Data Lake, DWH)
5. **Management** — управление качеством, версионирование, метаданные
6. **Analysis** — аналитика, ML-моделирование
7. **Visualization** — представление результатов
8. **Archival/Destruction** — архивация или удаление по policy

## БИЛЕТ №2
**1. Источники и способы генерации данных**

Источники:
- **Транзакционные системы** — ERP, CRM, POS-терминалы
- **IoT-устройства** — датчики, умные приборы, носимые устройства
- **Веб и мобильные приложения** — clickstream, логи, события
- **Социальные сети** — посты, комментарии, реакции
- **Открытые данные** — правительственные порталы, Kaggle, UCI
- **Сенсорные данные** — спутниковые снимки, медицинское оборудование

Способы генерации: **машинная** (автоматически: логи, IoT), **человеческая** (ввод данных, соцсети), **синтетическая** (сгенерированные датасеты для ML).

**2. Структурирование и форматы представления данных**

| Формат | Тип | Применение |
|---|---|---|
| CSV/TSV | Табличный | Простой обмен |
| JSON | Иерархический | API, NoSQL |
| XML | Иерархический | Enterprise интеграция |
| Parquet | Колоночный бинарный | Big Data аналитика |

**3. Характеристики и свойства Big Data**

Модель **5V**: Volume (терабайты+), Velocity (высокая скорость поступления), Variety (разные форматы), Veracity (неопределённость качества), Value (ценность после анализа).

Дополнительные характеристики: **Variability** (непоследовательность потоков), **Visualization** (сложность представления), **Viscosity** (сопротивление передаче).

## БИЛЕТ №3
**1. Методы сбора данных из различных источников**

- **Web scraping** — автоматический парсинг веб-страниц (BeautifulSoup, Scrapy, Selenium)
- **REST API** — стандартный HTTP-интерфейс для получения данных в JSON
- **Database extraction** — SQL-запросы, JDBC/ODBC подключения
- **File ingestion** — чтение CSV, Excel, PDF из файловых систем/FTP/S3
- **Stream ingestion** — Kafka consumer, MQTT-подписка для IoT
- **CDC (Change Data Capture)** — захват изменений из БД в реальном времени (Debezium)
- **Survey/manual input** — формы, опросы

**2. Интеграция разнородных данных**

Задача: объединить данные из разных источников с разными форматами, схемами, идентификаторами.

Методы:
- **Schema mapping** — сопоставление полей из разных схем
- **Entity resolution** — отождествление записей об одной сущности из разных источников (record linkage, fuzzy matching)
- **Data federation** — виртуальный слой над несколькими источниками без физического перемещения (Apache Drill, Presto)
- **Master Data Management (MDM)** — единый "золотой источник" для ключевых сущностей

**3. Проблемы полноты и достоверности данных**

- **Пропуски**: MCAR (случайные), MAR (зависят от других переменных), MNAR (зависят от пропущенного значения) — влияет на стратегию заполнения
- **Дубликаты**: точные и нечёткие (одна сущность с разными написаниями)
- **Противоречия**: одна запись с разными значениями в разных источниках
- **Устаревшие данные**: адреса, должности меняются
- Решения: data profiling, валидация при загрузке, golden record в MDM

## БИЛЕТ №4
**1. Процедуры очистки и подготовки данных**

Этапы:
1. **Аудит** — профилирование: статистика, распределения, nulls, уникальность
2. **Дедупликация** — удаление точных и fuzzy-дубликатов
3. **Коррекция типов** — строки → числа/даты
4. **Стандартизация форматов** — единый формат дат, телефонов, адресов
5. **Обработка пропусков** — удаление или импутация
6. **Обработка аномалий** — исправление или удаление выбросов
7. **Нормализация/масштабирование** — приведение к единому масштабу

**2. Методы обработки пропущенных значений**

**Удаление:**
- `dropna()` — только если пропусков мало (< 5%) и случайны (MCAR)

**Статистическая импутация:**
- Числовые: среднее (нет выбросов), медиана (есть выбросы), мода (категориальные)
- `df.fillna(df.median())`

**Алгоритмические методы:**
- **KNN Imputation** — заполнить на основе k ближайших соседей
- **Regression Imputation** — предсказать пропуск моделью по другим признакам
- **Multiple Imputation** (MICE) — создать несколько датасетов с разными вариантами

**Индикаторная переменная**: добавить бинарный признак `was_missing` — сам факт пропуска может нести информацию.

**3. Методы выявления аномалий**

- **Статистические**: Z-score ($|z| > 3$), IQR-метод (`< Q1 - 1.5·IQR` или `> Q3 + 1.5·IQR`)
- **Визуальные**: boxplot, scatter plot, histogram
- **ML-методы**:
  - **Isolation Forest** — аномалии изолируются быстрее (короткий путь в дереве)
  - **LOF (Local Outlier Factor)** — сравнение плотности точки с соседями
  - **Autoencoder** — высокая ошибка реконструкции = аномалия
  - **One-Class SVM** — обучение только на нормальных данных

## БИЛЕТ №5
**1. Этапы предобработки данных**

1. Анализ данных (EDA) → 2. Очистка (дубликаты, пропуски, аномалии) → 3. Трансформация (масштабирование, кодирование) → 4. Отбор признаков → 5. Разбиение (train/val/test)

**2. Масштабирование и нормализация признаков**

Зачем: алгоритмы на основе расстояний (KNN, SVM, PCA) чувствительны к масштабу.

- **Min-Max Normalization**: $x' = \frac{x - x_{min}}{x_{max} - x_{min}} \in [0, 1]$ — сохраняет форму распределения, чувствителен к выбросам
- **Standardization (Z-score)**: $x' = \frac{x - \mu}{\sigma}$ — среднее=0, std=1; устойчивее к выбросам
- **Robust Scaler**: $x' = \frac{x - median}{IQR}$ — использует медиану и IQR, устойчив к выбросам
- **Log Transform**: $x' = \log(x+1)$ — для правоскошенных распределений

**3. Кодирование категориальных переменных**

- **Label Encoding**: A→0, B→1, C→2 — только для ординальных переменных (иначе алгоритм думает, что B > A)
- **One-Hot Encoding (OHE)**: каждое значение → бинарный столбец. Проблема высокой кардинальности (1000 городов → 1000 столбцов)
- **Ordinal Encoding**: вручную задать числовой порядок (small=1, medium=2, large=3)
- **Target Encoding**: заменить категорию средним значением target по этой категории (риск leakage — применять только на train)
- **Frequency Encoding**: заменить частотой встречаемости
- **Embedding** (Deep Learning): low-dimensional dense vector для высококардинальных признаков

## БИЛЕТ №6
**1. Архитектуры хранения данных**

- **OLTP (Online Transaction Processing)** — оптимизирован для частых транзакций (INSERT/UPDATE/DELETE), нормализован, строчное хранение. PostgreSQL, MySQL, Oracle.
- **OLAP (Online Analytical Processing)** — оптимизирован для аналитических запросов (GROUP BY, aggregations), денормализован, колоночное хранение. Redshift, BigQuery, ClickHouse.
- **HTAP (Hybrid)** — оба сценария в одной системе. TiDB, SingleStore.

**2. Реляционные и документо-ориентированные базы**

| | Реляционные (RDBMS) | Документные (MongoDB) |
|---|---|---|
| Схема | Жёсткая (DDL) | Гибкая (schema-less) |
| Запросы | SQL (стандартный) | MQL (проприетарный) |
| Связи | JOIN через внешние ключи | Вложенные документы / $lookup |
| Масштабирование | Вертикальное | Горизонтальное (sharding) |
| ACID | Полный | Транзакции в v4.0+ |
| Лучше для | Связные данные, отчёты | Гибкая схема, иерархические данные |

**3. Процессы ETL и ELT**

**ETL** (Extract → Transform → Load): трансформация происходит до загрузки в хранилище. Используется в классических DWH (Informatica, Talend).

**ELT** (Extract → Load → Transform): сырые данные грузятся сразу, трансформация выполняется SQL-запросами внутри облачного DWH (dbt + BigQuery/Redshift). Подходит для облачных MPP-систем.

Ключевые инструменты: **Apache Airflow** (оркестрация), **dbt** (трансформации), **Fivetran/Airbyte** (коннекторы источников).

## БИЛЕТ №7
**1. Постановка задач анализа данных**

Процесс: **Business Question → Data Question → Method → Metric → Action**

Типы задач:
- **Описательная** (Descriptive): что произошло? → агрегации, сводные таблицы
- **Диагностическая** (Diagnostic): почему произошло? → корреляция, причинно-следственный анализ
- **Предиктивная** (Predictive): что произойдёт? → ML-модели
- **Предписывающая** (Prescriptive): что делать? → оптимизация, A/B тесты

Важно: правильная постановка задачи (CRISP-DM: Business Understanding → Data Understanding → ...).

**2. Описательные методы анализа**

- **Меры центральной тенденции**: среднее $\bar{x} = \frac{1}{n}\sum x_i$, медиана (50-й процентиль), мода
- **Меры разброса**: дисперсия $\sigma^2 = \frac{1}{n}\sum(x_i - \bar{x})^2$, стандартное отклонение $\sigma$, IQR
- **Форма распределения**: асимметрия (skewness), эксцесс (kurtosis)
- **Корреляционный анализ**: матрица корреляций, heatmap
- **Частотный анализ**: таблицы contingency, value_counts()
- **Визуализация**: гистограммы, boxplots, scatter matrices

**3. Диагностический анализ данных**

Цель — понять причины наблюдаемых паттернов:
- **Drill-down** — декомпозиция метрики по измерениям (снизился ли revenue в конкретном регионе?)
- **Cohort analysis** — сравнение групп пользователей по времени регистрации
- **A/B анализ** — сравнение версий для выявления причин различий
- **Correlation analysis** — изучение связей между переменными (не равно причинно-следственная связь!)
- **Root cause analysis** — методы типа "5 Почему", Fishbone diagram
- **Simpson's Paradox** — агрегированный тренд может быть противоположен подгрупповым

## БИЛЕТ №8
**1. Прогнозирование как задача анализа данных**

Прогнозирование (forecasting) — предсказание будущих значений на основе исторических данных. Типы:
- **Point forecast** — одно значение (ожидаемые продажи: 1000 единиц)
- **Interval forecast** — диапазон с вероятностью (95% интервал: 900–1100)
- **Probabilistic forecast** — полное распределение вероятностей

Горизонт: краткосрочный (часы–дни), среднесрочный (недели–месяцы), долгосрочный (годы).

**2. Анализ временных зависимостей**

Компоненты временного ряда:
- **Trend** — долгосрочное направление изменений
- **Seasonality** — регулярные циклические паттерны (ежегодные, еженедельные)
- **Cyclicality** — нерегулярные длинные циклы (экономические)
- **Residual/Noise** — случайный компонент

Методы: **ACF/PACF** (автокорреляция для определения порядка ARIMA), **STL decomposition** (Seasonal-Trend decomposition using Loess), **Fourier analysis** (частотный анализ).

Модели: **ARIMA(p,d,q)**, **SARIMA** (сезонная), **Exponential Smoothing** (Holt-Winters), **Prophet** (Facebook), **LSTM**.

**3. Практическое применение аналитических моделей**

- **Demand forecasting** — планирование запасов (ARIMA, XGBoost + lag features)
- **Financial forecasting** — прогноз выручки, cash flow
- **Energy demand** — прогноз потребления электроэнергии (влияние температуры, дня недели)
- **Traffic forecasting** — оптимизация дорожной сети
- **Churn prediction** — предсказание оттока клиентов в следующие N дней (бинарная классификация)
- **Model deployment**: MLflow для версионирования, Airflow для переобучения по расписанию

## БИЛЕТ №9
**1. Статистические основы анализа данных**

Статистика — раздел математики для сбора, организации, анализа и интерпретации данных. Разделы:
- **Описательная статистика** — резюмирует данные выборки (среднее, std, гистограммы)
- **Инференциальная статистика** — делает выводы о генеральной совокупности по выборке (доверительные интервалы, гипотезы)

**Распределения**: нормальное (N(μ,σ²)), пуассоновское (события в единицу времени), биномиальное (число успехов в n попытках), равномерное.

**Центральная предельная теорема**: при достаточно большой выборке среднее выборок → нормальное распределение независимо от формы генеральной совокупности.

**2. Оценка центральных тенденций**

- **Среднее (mean)**: $\bar{x} = \frac{1}{n}\sum_{i=1}^{n}x_i$ — чувствительно к выбросам
- **Медиана**: значение, делящее отсортированный ряд пополам — устойчива к выбросам
- **Мода**: наиболее частое значение — для категориальных данных
- **Усечённое среднее** (trimmed mean): среднее после отброса k% крайних значений
- **Взвешенное среднее**: $\bar{x}_w = \frac{\sum w_i x_i}{\sum w_i}$

Когда использовать: нет выбросов → mean; выбросы или скошенное распределение → median; категориальные → mode.

**3. Оценка разброса и вариации**

- **Дисперсия**: $s^2 = \frac{1}{n-1}\sum(x_i - \bar{x})^2$ (несмещённая оценка для выборки)
- **Стандартное отклонение**: $s = \sqrt{s^2}$ — в тех же единицах, что и переменная
- **MAD (Mean Absolute Deviation)**: $\frac{1}{n}\sum|x_i - \bar{x}|$ — устойчивее к выбросам
- **IQR**: Q3 - Q1 (межквартильный размах) — устойчив к выбросам
- **Коэффициент вариации**: $CV = \frac{s}{\bar{x}} \cdot 100\%$ — относительный разброс

## БИЛЕТ №10
**1. Методы корреляционного анализа**

Корреляция измеряет силу и направление линейной связи между двумя переменными.

- **Коэффициент Пирсона**: $r = \frac{\sum(x_i - \bar{x})(y_i - \bar{y})}{\sqrt{\sum(x_i-\bar{x})^2 \sum(y_i-\bar{y})^2}}$, $r \in [-1, 1]$ — для непрерывных, нормальных данных
- **Коэффициент Спирмена** ($\rho$) — ранговая корреляция, устойчива к выбросам, для монотонных нелинейных связей
- **Коэффициент Кендалла** ($\tau$) — ранговая, более устойчива при малых выборках
- **Point-Biserial** — между непрерывной и бинарной переменной
- **Phi-coefficient** — между двумя бинарными переменными

**2. Линейные и нелинейные зависимости**

**Линейная**: $y = a + bx$ — постоянное изменение y при изменении x. Хорошо улавливается Пирсоном.

**Нелинейные**: Спирмен/Кендалл улавливают монотонные нелинейные связи. Для произвольных зависимостей:
- **Mutual Information** — из теории информации, улавливает любые зависимости
- **Distance Correlation** — 0 только при полной независимости
- **HSIC (Hilbert-Schmidt Independence Criterion)**

Визуализация: scatter plot для обнаружения типа зависимости до применения метрики.

**3. Интерпретация статистических связей**

- $|r| < 0.3$ — слабая связь; $0.3–0.7$ — умеренная; $> 0.7$ — сильная
- **Корреляция ≠ причинно-следственная связь** (мороженое и утопления коррелируют через лето)
- **Spurious correlation** — случайная корреляция в больших данных (p-hacking)
- **Confounding variable** — скрытая третья переменная, вызывающая корреляцию
- **Partial correlation** — корреляция при фиксации confounders
- **p-value** ($< 0.05$) — статистическая значимость, но не практическая значимость (effect size!)

## БИЛЕТ №11
**1. Принципы визуального анализа данных**

- **Preattentive attributes** — цвет, размер, позиция воспринимаются мгновенно до осознанного внимания → используй их для выделения главного
- **Gestalt principles** — группировка, близость, подобие, непрерывность — принципы восприятия паттернов
- **Data-ink ratio** (Tufte): максимизировать информацию на единицу "чернил", убирать chartjunk
- **Visual encoding hierarchy** (Cleveland & McGill): позиция > длина > угол > площадь > цвет/насыщенность

**2. Выбор адекватных методов визуализации**

| Задача | Тип графика |
|---|---|
| Сравнение категорий | Bar chart (горизонтальный для многих категорий) |
| Временной ряд | Line chart |
| Распределение | Histogram, KDE plot, violin |
| Корреляция двух переменных | Scatter plot |
| Корреляционная матрица | Heatmap |
| Иерархия/части целого | Treemap (не pie!) |
| Распределение + сравнение групп | Boxplot |
| Геопространственные | Choropleth, точечная карта |
| Поток/переходы | Sankey diagram |

## БИЛЕТ №15
**1. Регрессионные методы анализа данных**

Регрессия — предсказание непрерывной целевой переменной $y$ по набору признаков $X$.

**Линейная регрессия**: $\hat{y} = w_0 + w_1x_1 + ... + w_px_p$

Оценка коэффициентов методом наименьших квадратов (OLS): минимизация $\sum(y_i - \hat{y}_i)^2$.

Предположения OLS (Gauss-Markov): линейность, гомоскедастичность, отсутствие мультиколлинеарности, нормальность остатков.

**2. Линейные и полиномиальные модели**

**Полиномиальная регрессия**: добавление признаков-степеней $x, x^2, x^3, ..., x^d$.
```python
from sklearn.preprocessing import PolynomialFeatures
poly = PolynomialFeatures(degree=3)
X_poly = poly.fit_transform(X)
```

**Ridge регрессия** (L2): $\min ||y - Xw||^2 + \alpha||w||^2$ — штраф за большие коэффициенты, снижает мультиколлинеарность.

**Lasso регрессия** (L1): $\min ||y - Xw||^2 + \alpha||w||_1$ — штраф вызывает разреженность (feature selection).

**ElasticNet**: комбинация L1 + L2.

**3. Метрики оценки регрессионных моделей**

- **MAE**: $\frac{1}{n}\sum|y_i - \hat{y}_i|$ — в тех же единицах, устойчив к выбросам
- **RMSE**: $\sqrt{\frac{1}{n}\sum(y_i - \hat{y}_i)^2}$ — штрафует большие ошибки
- **R² (Coefficient of Determination)**: $1 - \frac{SS_{res}}{SS_{tot}} \in (-\infty, 1]$ — доля объяснённой дисперсии
- **Adjusted R²**: корректирует R² на число признаков (не растёт при добавлении ненужных)
- **MAPE**: $\frac{1}{n}\sum\frac{|y_i - \hat{y}_i|}{y_i} \cdot 100\%$ — относительная ошибка в %

## БИЛЕТ №16
**1. Формализация задач классификации**

Задача: по вектору признаков $x \in \mathbb{R}^p$ предсказать метку класса $y \in \{1, ..., K\}$.

**Бинарная классификация** ($K=2$): spam/not-spam, болен/здоров.
**Многоклассовая** ($K>2$): OvR (One-vs-Rest) или OvO (One-vs-One).
**Многометочная**: объект может принадлежать нескольким классам одновременно.

**Вероятностная классификация**: модель выдаёт $P(y=k|x)$, порог для принятия решения.

**2. Алгоритмы классификации данных**

- **Logistic Regression**: $P(y=1|x) = \sigma(w^Tx) = \frac{1}{1+e^{-w^Tx}}$, обучение через cross-entropy loss
- **Decision Tree**: рекурсивное разбиение по признаку/порогу, критерий Gini или энтропия
- **Random Forest**: **bagging** (bootstrap samples) + случайные подмножества признаков → усреднение предсказаний → снижение variance
- **XGBoost/LightGBM**: **boosting** — последовательное обучение, каждое дерево корректирует ошибки предыдущего → снижение bias
- **SVM**: максимизация margin: $\max \frac{2}{||w||}$ при правильной классификации, kernel trick для нелинейных границ

**3. Метрики качества классификации**

Из confusion matrix (TP, FP, TN, FN):
- **Accuracy**: $\frac{TP+TN}{TP+FP+TN+FN}$ — не подходит при дисбалансе классов
- **Precision**: $\frac{TP}{TP+FP}$ — точность: из предсказанных позитивных, сколько реально позитивных
- **Recall (Sensitivity)**: $\frac{TP}{TP+FN}$ — полнота: из реальных позитивных, сколько поймали
- **F1-score**: $\frac{2 \cdot P \cdot R}{P+R}$ — гармоническое среднее precision и recall
- **ROC-AUC**: площадь под кривой TPR vs FPR — устойчив к дисбалансу, не зависит от порога
- **PR-AUC** — лучше чем ROC при сильном дисбалансе

## БИЛЕТ №17
**1. Теоретические основы кластеризации**

Кластеризация — обучение без учителя: разбить данные на группы (кластеры) так, чтобы объекты внутри кластера были похожи друг на друга, а между кластерами — различны.

Применения: сегментация клиентов, группировка документов, аномалии, сжатие изображений (vector quantization).

Расстояния: Евклидово ($L_2$), Манхэттенское ($L_1$), косинусное (для текста), Хэмминговое (для бинарных).

**2. Алгоритм K-Means и его свойства**

Алгоритм Ллойда:
1. Инициализация: выбрать k центроидов (случайно или K-Means++)
2. Присваивание: каждую точку к ближайшему центроиду
3. Обновление: пересчитать центроиды как среднее точек кластера
4. Повторять 2-3 до сходимости

Сложность: $O(n \cdot k \cdot d \cdot iter)$. Сходится к локальному минимуму.

**K-Means++**: умная инициализация — центроиды выбираются с вероятностью пропорциональной расстоянию до ближайшего уже выбранного центроида. Ускоряет сходимость.

Ограничения: нужно задавать k, кластеры сферические, чувствителен к выбросам и масштабу.

**3. Оценка качества кластеризации**

Внешние метрики (есть истинные метки):
- **ARI (Adjusted Rand Index)** — скорректированный на случай rand index
- **NMI (Normalized Mutual Information)**

Внутренние метрики (без меток):
- **Silhouette Coefficient**: $s = \frac{b-a}{\max(a,b)}$ ∈ [-1,1], где $a$ — среднее расстояние внутри кластера, $b$ — до ближайшего чужого кластера. Ближе к 1 — лучше.
- **Elbow method** — plot inertia vs k, искать "локоть"
- **Davies-Bouldin Index** — среднее отношение разброса к расстоянию между кластерами

## БИЛЕТ №18
**1. Проблема высокой размерности данных**

**"Проклятие размерности"** (curse of dimensionality): при росте числа признаков:
- Объём пространства растёт экспоненциально → данные становятся редкими
- Все точки становятся примерно равноудалёнными (расстояния теряют смысл)
- Нужно экспоненциально больше данных для достаточной плотности
- Переобучение моделей

Следствие: KNN плохо работает в высоких размерностях, кластеризация деградирует.

**2. Метод главных компонент (PCA)**

PCA — линейное преобразование, проецирующее данные на ортогональные оси максимальной дисперсии (главные компоненты):

1. Центрировать данные: $X_{centered} = X - \bar{X}$
2. Вычислить матрицу ковариации: $\Sigma = \frac{1}{n}X^TX$
3. Найти собственные вектора/значения: $\Sigma v = \lambda v$
4. Выбрать k компонент с наибольшими $\lambda_i$
5. Проекция: $Z = X \cdot V_k$

```python
from sklearn.decomposition import PCA
pca = PCA(n_components=2)
X_reduced = pca.fit_transform(X_scaled)
print(pca.explained_variance_ratio_)  # доля дисперсии каждой компоненты
```

**3. Интерпретация результатов PCA**

- **Explained variance ratio** — сколько % дисперсии объясняет каждая компонента
- **Scree plot** — график eigenvalues, ищем "локоть" для выбора k
- **Cumulative explained variance** — выбирать k, чтобы объяснить 85–95% дисперсии
- **Biplot** — визуализация точек + векторов нагрузок (loadings): какие признаки вносят вклад в PC1/PC2
- Ограничения: линейность (нелинейные: t-SNE, UMAP, Kernel PCA), интерпретируемость теряется

## БИЛЕТ №19
**1. Модели временных рядов**

- **AR(p) — Autoregressive**: $y_t = c + \phi_1 y_{t-1} + ... + \phi_p y_{t-p} + \epsilon_t$
- **MA(q) — Moving Average**: $y_t = c + \theta_1\epsilon_{t-1} + ... + \theta_q\epsilon_{t-q} + \epsilon_t$
- **ARIMA(p,d,q)**: AR + I (differencing для стационарности) + MA. `from statsmodels.tsa.arima.model import ARIMA`
- **SARIMA(p,d,q)(P,D,Q,s)**: сезонная ARIMA
- **Exponential Smoothing** (ETS): взвешенное среднее прошлых значений с экспоненциальным затуханием
- **Prophet** (Meta): trend + seasonality + holidays. Устойчив к пропускам и аномалиям.
- **LSTM/GRU**: рекуррентные нейросети, хорошо улавливают долгосрочные зависимости

**2. Методы анализа сезонности**

- **Visual inspection**: plot временного ряда, посмотреть на повторяющиеся паттерны
- **STL decomposition** (Seasonal and Trend decomposition using Loess): разложение на trend + seasonal + residual
- **ACF plot**: автокорреляция при lag кратном периоду (lag=12 для месячных данных) → пики на ACF
- **Seasonality detection**: тест Квано-Стюарта, Фурье-анализ
- **Seasonal differencing**: $y_t' = y_t - y_{t-s}$ для удаления сезонности

```python
from statsmodels.tsa.seasonal import seasonal_decompose

```

**3. Оценка точности прогнозирования**

- **MAE, RMSE, MAPE** (см. билет №15) — стандартные метрики
- **sMAPE** (symmetric MAPE): $\frac{2|y_t - \hat{y}_t|}{|y_t|+|\hat{y}_t|}$ — избегает деления на ноль
- **MASE** (Mean Absolute Scaled Error): нормализует MAE на MAE наивной модели (random walk) → не зависит от масштаба
- **Walk-forward validation**: скользящее обучение/предсказание, более реалистично чем train/test split
- **Residual analysis**: остатки должны быть белым шумом (нет автокорреляции) — тест Льюнга-Бокса

**2. Методы поиска закономерностей**

- **Association Rule Mining**: частые множества предметов → правила вида $A \Rightarrow B$.
  - **Support**: $P(A \cap B)$ — как часто встречается вместе
  - **Confidence**: $P(B|A) = P(A \cap B)/P(A)$ — надёжность правила
  - **Lift**: $Confidence/P(B)$ — насколько правило лучше случайного
  - Алгоритмы: **Apriori** (последовательная генерация), **FP-Growth** (дерево частых паттернов, быстрее)

- **Sequential Pattern Mining**: PrefixSpan — последовательности событий (клиент купил A, потом B, потом C)

- **Decision Rules**: C4.5, RIPPER — извлечение IF-THEN правил из деревьев

**3. Оценка полезности найденных правил**

- **Support threshold**: минимальная частота (убирает редкие правила)
- **Confidence threshold**: минимальная надёжность
- **Lift > 1**: правило информативнее случайного
- **Conviction**: $\frac{1-P(B)}{1-Confidence}$ — альтернатива confidence
- **Практическая значимость**: найденный паттерн должен быть **actionable** (применимым) и **novel** (новым для бизнеса)
- **Проблема множественных сравнений**: при поиске среди тысяч правил нужна поправка Бонферрони

## БИЛЕТ №25
**1. Методы защиты данных в аналитике**

- **Anonymization** — необратимое удаление идентификаторов (PII): нельзя восстановить исходные данные
- **Pseudonymization** — замена идентификаторов псевдонимами (можно восстановить с ключом)
- **Data masking** — скрытие части данных (email: j***@gmail.com, credit card: ****-****-****-1234)
- **Differential Privacy** — добавление калиброванного шума к результатам запросов; ε-differential privacy: $P[M(D) \in S] \leq e^\epsilon \cdot P[M(D') \in S]$
- **k-Anonymity** — каждая запись неотличима от минимум k-1 других по квазиидентификаторам
- **Synthetic data generation** — создание статистически похожих, но ненастоящих данных (CTGAN)

**2. Контроль доступа к данным**

- **RBAC (Role-Based Access Control)**: права назначаются ролям, пользователи получают роли
- **ABAC (Attribute-Based Access Control)**: доступ определяется атрибутами субъекта, ресурса и контекста
- **Row-Level Security (RLS)**: фильтрация строк в зависимости от пользователя (PostgreSQL, Tableau, Power BI)
- **Column-Level Security**: скрытие чувствительных столбцов (PII) для определённых ролей
- **Apache Ranger**: централизованная авторизация для Hadoop-экосистемы

**3. Обеспечение конфиденциальности**

- **GDPR-требования**: согласие на обработку, право на доступ, право на удаление, privacy by design
- **Data minimization**: собирать только необходимые данные для конкретной цели
- **Purpose limitation**: не использовать данные для иных целей, чем при сборе
- **Privacy by Design** (PbD): конфиденциальность встроена в архитектуру системы, а не добавлена постфактум
- **Federated Learning**: обучение ML-модели без передачи данных на центральный сервер

## БИЛЕТ №28
**1. Экспериментальный дизайн в анализе данных**

**A/B тестирование** — контролируемый эксперимент: случайное разбиение пользователей на контрольную (A) и тестовую (B) группы, измерение разницы в метрике.

Ключевые понятия:
- **Randomization unit**: пользователь, сессия, устройство
- **Treatment**: изменение (новый алгоритм, новый UI)
- **Control group**: без изменений
- **Holdout group**: группа без изменений для долгосрочного сравнения

Требования: достаточный размер выборки (power analysis), отсутствие interference (SUTVA), правильная длительность.

**2. Проверка статистических гипотез**

Процедура:
1. Сформулировать $H_0$ (нет эффекта) и $H_1$ (есть эффект)
2. Выбрать критерий и уровень значимости $\alpha$ (обычно 0.05)
3. Вычислить тест-статистику
4. Сравнить p-value с $\alpha$

Тесты:
- **t-test (независимый)**: сравнение средних двух независимых групп (нормальность!)
- **Mann-Whitney U**: непараметрический аналог t-test
- **Chi-squared test**: ассоциация между категориальными переменными
- **ANOVA**: сравнение средних трёх и более групп

Ошибки:
- **Type I (False Positive)**: отвергаем $H_0$ когда она верна (α-error)
- **Type II (False Negative)**: не отвергаем $H_0$ когда она ложна (β-error)
- **Statistical Power** = $1-\beta$ (вероятность обнаружить реальный эффект)

**3. Интерпретация статистических результатов**

- **p-value ≠ вероятность того что H₀ верна**; это $P(\text{данные} | H_0)$
- **p < 0.05** — статистически значимо, но может быть практически незначимым
- **Effect size** (Cohen's d, Cramér's V): практическая значимость, не зависит от размера выборки
- **Confidence Interval**: диапазон правдоподобных значений параметра с вероятностью (1-α)
- **Multiple comparisons problem**: 20 тестов при α=0.05 → 1 ложно значимый по случайности → поправка Бонферрони или FDR (Benjamini-Hochberg)
- **Bayesian A/B testing** — вероятность того, что B лучше A, более интуитивна чем p-value

## БИЛЕТ №29 (Билет №29 — Формирование признакового пространства)
**1. Формирование признакового пространства**

**Feature engineering** — процесс создания информативных признаков из сырых данных для улучшения качества модели. "Features matter more than algorithms" (Andrew Ng).

Типы операций:
- **Extraction** — извлечение признаков из raw data (пиксели → edges → shapes)
- **Construction** — создание новых признаков (age × income, is_weekend)
- **Transformation** — преобразование (log, sqrt, polynomial)
- **Interaction features** — произведения/отношения пар признаков
- **Domain-specific features** — вычисление на основе знания предметной области

**2. Методы отбора признаков**

**Filter methods** (независимо от модели):
- Дисперсия: `VarianceThreshold` — удалить константные признаки
- Корреляция с target: Pearson, Spearman, point-biserial
- Mutual Information: нелинейные зависимости
- Chi-squared test (для категориальных)

**Wrapper methods** (с учётом модели):
- **RFE** (Recursive Feature Elimination): обучить модель, удалить слабейшие, повторить
- Forward/Backward selection: жадное добавление/удаление признаков

**Embedded methods** (внутри модели):
- **L1 regularization (Lasso)**: обнуляет веса неважных признаков
- **Feature importance** (Tree-based): `rf.feature_importances_`
- **SHAP values**: Shapley-based глобальная важность признаков

**3. Методы генерации признаков**

- **Polynomial features**: $x_1^2, x_2^2, x_1 x_2$ — для нелинейных зависимостей
- **Binning/Discretization**: age → [18-25], [26-35], [36-50] — для нелинейных эффектов
- **Date/Time features**: hour, day_of_week, is_holiday, days_since_event
- **Text features**: TF-IDF, n-grams, BERT embeddings, word count, sentiment
- **Aggregation features**: среднее/std/max по пользователю за последние 30 дней
- **Lag features** (для временных рядов): $y_{t-1}, y_{t-7}$ — автокорреляция
- **Rolling statistics**: скользящее среднее, скользящая std
- **Target encoding**: среднее target по категории (с cross-validation для избежания утечки)
- **Clustering features**: расстояние до центроида кластера как дополнительный признак

CRISP-DM (Cross-Industry Standard Process for Data Mining):
1. **Business Understanding** — цели, KPI, критерии успеха

```
Raw Data → Data Ingestion → Data Lake (Bronze)

         → Feature Engineering → Gold/Feature Store
         → Model Training → Model Registry (MLflow)
         → Model Serving → Monitoring → Alert → Retrain
```

- **AutoML** (H2O, AutoSklearn, TPOT): автоматический подбор алгоритма и гиперпараметров
